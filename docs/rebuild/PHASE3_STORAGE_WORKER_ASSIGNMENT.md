## SQLite initialization, upgrade and backup

Native per-connection pragmas: WAL, synchronous FULL, foreign_keys ON, busy_timeout 30000. Preserve SQLAlchemy logical entities/UUID/enums/JSON, UTC interpretation and default Docker PostgreSQL path. The old migration ledger through `005_large_file_size_bigint` remains recognized. Add `006_lancedb_index_journal`.

Determine applied revisions BEFORE any metadata mutation. Reject unknown/future/non-contiguous revisions without changing database bytes/schema. For a database with no revision ledger but existing tables, identify it as the explicit legacy preview path; back it up, reconcile only the known additive project columns and establish the known revisions in one transaction. New empty databases create current tables and ledger transactionally. Existing known revisions receive only unapplied migration steps; marking follows each successful step in the same transaction. Keep create_all for missing known tables, not as an excuse to skip revision checks. Before upgrading an existing database, take a consistent online SQLite backup outside the upgrade transaction through the existing backup helper; ensure backup succeeds before mutation. Avoid deadlock by never opening the backup connection while holding an SQLite write transaction. If current async engine.begin wrapper must change to preflight/backup before begin, do that within allowed database.py.

Restore requires caller-disposed connections. Validate backup integrity and FK checks. Preserve current consistent backup, checkpoint/close before replace, and handle owned `-wal`/`-shm` files so stale WAL cannot replay over restored data. Use explicit target paths, atomic replace, no directory-wide delete. Keep API compatibility and clear errors; preserve recovery evidence on failure. Never copy only a live hot database file.

## Durable index and LanceDB boundary

Desktop native must use LanceDB only: no Qdrant-local or SQLite cosine fallback after a failure. Keep non-native Docker Qdrant code intact in the dedicated repo, but original aive itself is never edited. The native adapter can expose focused methods rather than pretend to be a Qdrant implementation. Keep RAG public ensure_collection, get_collection_stats, reset_collection, ingest_course_material, ingest_transcript, add_chunks, search and delete_by_source signatures/results. Preserve existing page and transcript chunk algorithms and metadata; don't change agent prompts. Remove the duplicate add_chunks definition by preserving the effective default/source behavior and returning a useful count to its callers.

Use engine.sqlite3 authoritative tables for sources, chunk snapshots and pending index operations. Include source_type/id, configuration signature, generation, stable UUIDv5 chunk identity, text, exact flattened payload metadata and embedded vector snapshot. Serialize vectors as JSON or explicit float blob with validated dimension. No provider request is allowed while a SQLite transaction is open. Compute all embeddings before journal transaction; reject wrong embedding count/dimensions/nonfinite/zero-norm vectors before mutation. Query vectors get the same validation. Configuration signature contains selected actual provider identity/model/dimensions (not just a hardcoded default); inspect LLMService provider metadata/default_model and settings. If the embedding configuration changes, raise an explicit mismatch/reindex-required error rather than mixing vectors or silently clearing/re-embedding. Keep original EMBEDDING_DIMENSIONS selected setting.

Lance table uses fixed-size float32 vector column, stable chunk_id, generation-specific row_id, source_type, source_id, configuration signature, generation and payload JSON. Use a deterministic source generation hash of chunks/vectors/config so replay is idempotent. Stable chunk_id UUIDv5 derives source_type/id/chunk_index/config; Lance row_id also incorporates generation, keeping old published rows until replacement publication. SQL strings must quote literals safely, never interpolate unescaped source IDs or metadata.

Replacement: short SQLite transaction saves complete new chunk/vector snapshots and pending operation, leaving previous published generation visible. Off-thread Lance merge/upsert new generation by row_id, verify expected complete row count, then short SQLite transaction publishes generation and marks complete. Only then clean old Lance rows/snapshots idempotently. Keep pending snapshots if any step fails. Delete: persist tombstone/pending delete and remove published visibility in one SQLite transaction, delete matching Lance rows, then mark complete. Reset likewise must be recoverable and never report success when mutation failed. Serialize native mutations with an owned lock; don't hold that lock during provider embedding calls.

Startup ensure_collection replays unfinished replacements/deletes from saved vectors WITHOUT network calls. Replaying cannot publish a partial generation. Search sees only SQLite-published complete generations and configuration; apply their visibility predicate AND requested source_type/source_id filters BEFORE nearest-neighbor ranking/limit. Missing/failed index is an explicit error; empty healthy index is zero hits. It is acceptable to hold an adapter lock across off-thread local query to prevent mutation races. The synchronous Lance operations run in asyncio.to_thread so API event loop remains responsive.

Use `.distance_type('cosine').bypass_vector_index()` and prefiltering, with no ANN index created. Similarity is `1 - _distance`; threshold filtering uses the unrounded similarity and <=0 means no threshold, then round score to four decimals. Preserve top_k behavior/result text/source/type/index/metadata shape. Stats count published complete chunks and explicitly label backend lancedb; don't count unpublished generations. No fake available capability if import/open/query/recovery fails. Provide a close hook if Lance owns resources, but report runtime wiring needed without editing runtime.py.

Primary documentation verified by main: https://docs.lancedb.com/search/vector-search/ (explicit cosine, bypass for exact kNN), https://docs.lancedb.com/search/filtering/ (prefilter), https://docs.lancedb.com/tables/update/ (merge operations).
